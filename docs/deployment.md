# Deployment

Recommended topology: **MongoDB Atlas** (database) · **Render / Railway / AWS** (API) · **Vercel / Netlify** (SPA) · **Cloudinary** (images) · **Razorpay** (payments) · any SMTP provider (email).

## 1. Database – MongoDB Atlas

1. Create a cluster (M10+ for production; M0 works for staging). Atlas clusters are replica sets, so multi-document transactions are enabled automatically.
2. Create a database user with `readWrite` on the app database only.
3. Allow the API's egress IPs (or use private endpoints / VPC peering).
4. Copy the SRV string into `MONGO_URI`, e.g. `mongodb+srv://app:<password>@cluster0.xxxxx.mongodb.net/bluemart?retryWrites=true&w=majority`.
5. Indexes: in production `autoIndex` is disabled. Build them once after the first deploy (and after schema changes). Unique emails, webhook de-duplication and admin search depend on them. The simplest place is the Render service's **Shell** tab, where the production variables are already set (no connection string on your machine or in shell history):

   ```bash
   # Render Shell – run from the server directory (cd server if the shell opens at the repository root)
   node -e "import('./src/config/db.js').then(async ({connectDatabase}) => { await connectDatabase(); const m = await import('./src/models/index.js'); for (const M of Object.values(m)) if (M?.syncIndexes) await M.syncIndexes(); process.exit(0); })"
   ```

   On the free plan (no Shell), prefix the service's start command with the same `node -e "..." &&` for one deploy, then restore `npm start`. Running it elsewhere requires the full production environment (`NODE_ENV=production` also validates `CLIENT_URL`, `SERVER_URL` and both JWT secrets). `syncIndexes` also drops indexes that are not declared in the schemas, so on an existing database review them first.

## 2. API – Render (blueprint included)

`render.yaml` defines the web service (`rootDir: server`, health check `/health`). The build (`npm ci --omit=dev` inside `server/`) resolves the root `package-lock.json` through npm workspaces and installs only the API's production dependencies.

1. New → Blueprint → select the repository.
2. Fill the `sync: false` variables (see table below). JWT secrets are generated by Render. Leave `TRUST_PROXY` blank.
3. After the first deploy, note the service URL (e.g. `https://bluemart-api.onrender.com`; Render appends a suffix when the name is taken) and set `SERVER_URL` to it.

**Railway**: create a service from the repo with root directory `server`, start command `npm start`, and add the same variables.
**AWS**: build `server/Dockerfile` (ECS Fargate / App Runner). Put it behind an ALB with HTTPS; the app sets `trust proxy` so rate limiting sees real client IPs.

### Server environment

| Variable | Required | Notes |
| --- | --- | --- |
| `NODE_ENV` | ✔ | `production` |
| `PORT` | – | Provided by the platform |
| `MONGO_URI` | ✔ | Atlas connection string |
| `MONGO_DB_NAME` | – | Database name; overrides the one in `MONGO_URI` (which otherwise defaults to `test`) |
| `CLIENT_URL` | ✔ | Storefront origin(s), comma-separated. First entry is used in email links |
| `SERVER_URL` | ✔ | Public API origin (sitemap / robots) |
| `JWT_SECRET`, `JWT_REFRESH_SECRET` | ✔ | ≥ 32 chars, different values |
| `COOKIE_DOMAIN` | – | Only when client & API share a parent domain (e.g. `.bluemart.store`) |
| `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET` | for online payments | Without them only COD is offered |
| `RAZORPAY_WEBHOOK_SECRET` | for online payments | Must match the dashboard webhook secret |
| `CLOUDINARY_*` | for uploads | Without them admins can still add image URLs |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `EMAIL_FROM` | for email | Without SMTP, emails are only logged |
| `LOG_LEVEL` | – | `info` by default |
| `TRUST_PROXY` | – | Proxy hops (integer 0–3, default `1`). Leave blank on Render, including behind the Vercel proxy – see below |
| `REDIS_URL` | – | Not used by the code today |

> **Cookies across sites.** The SPA (`*.vercel.app`) and API (`*.onrender.com`) are different sites, and browsers such as Safari block third-party cookies. The Vercel deployment therefore proxies `/api/*` to Render (`client/vercel.json`) and builds with `VITE_API_URL=/api/v1`, so the browser only talks to the storefront origin and the auth cookies are first-party. Leave `COOKIE_DOMAIN` empty. (Alternative: custom domains `www.` + `api.` with `COOKIE_DOMAIN=.your-domain`.)

### Client IP behind the proxy (`TRUST_PROXY`)

Rate limits and session records use `req.ip`, derived from `X-Forwarded-For` by Express's `trust proxy` hop count.

**Verified on the live deployment (Sept 2026): keep the default `1` (leave `TRUST_PROXY` blank).** Requests through the Vercel proxy and direct requests from the same client shared one `RateLimit` counter, so `1` already resolves the real client IP behind Vercel. A fake `X-Forwarded-For` sent through Vercel was ignored, and fake values sent directly to Render did not produce per-value counters, so IP-based limits cannot be evaded by rotating the header. `2` is not needed and could make the header spoofable.

To re-check after infrastructure changes, call `https://<vercel-domain>/api/v1/payments/config` (an uncached GET) through Vercel and directly on Render from the same machine, then from a second network, and compare the `RateLimit` response header.

## 3. Frontend – Vercel or Netlify

- **Vercel:** import the repo, set *Root Directory* = `client`, Node.js 22.x. `client/vercel.json` configures, in order: the `/api/*` proxy to Render, the `/sitemap.xml` proxy, the SPA fallback (which excludes `api/`), and cache/security headers.
  - **Before the first deploy**, replace both `https://replace-with-render-backend-url.invalid` destinations in `client/vercel.json` with the verified Render URL. The `.invalid` placeholder never resolves, so a forgotten replacement fails loudly instead of sending traffic elsewhere.
- **Netlify:** set *Base directory* = `client`; `client/netlify.toml` configures the build and SPA redirect (add an equivalent `/api/*` proxy redirect if you use it).

Client environment (build-time, public – never put secrets here; changes need a redeploy):

| Variable | Value |
| --- | --- |
| `VITE_API_URL` | `/api/v1` (same-origin, via the proxy) |
| `VITE_SITE_URL` | `https://<vercel-domain>` (canonical URLs, robots.txt sitemap line) |
| `VITE_SITE_NAME` | `BlueMart` |

`CLIENT_URL` on Render must equal the storefront origin exactly (e.g. `https://<vercel-domain>`, no trailing slash). Requests from other origins, including Vercel preview URLs, are rejected by CORS and the CSRF origin check unless added to the comma-separated list.

### Sitemap & robots

- The API serves a live `GET /sitemap.xml` (URLs built from `CLIENT_URL`); on Vercel, `/sitemap.xml` is proxied to it.
- `vite build` rewrites the `Sitemap:` line of `client/public/robots.txt` to `<VITE_SITE_URL>/sitemap.xml`, or removes it when `VITE_SITE_URL` is not a public absolute URL (unset, relative or localhost), so the localhost development value never ships.

## 4. Razorpay

1. Dashboard → Settings → API Keys → generate (test first, then live).
2. Dashboard → Webhooks → add `https://<render-domain>/api/v1/payments/razorpay/webhook` (the Render URL directly, not the Vercel proxy), set a secret (`RAZORPAY_WEBHOOK_SECRET`), subscribe to `payment.captured`, `payment.failed`, `order.paid`, `refund.processed`, `refund.failed`.
3. Test with Razorpay test cards/UPI (`success@razorpay`) before switching to live keys.

## 5. Cloudinary

Create a product environment, copy cloud name / API key / secret. Uploaded assets go to `<CLOUDINARY_FOLDER>/{products,categories,brands,reviews}` and are converted to WebP (max 2000px).

## 6. Email

Use a transactional provider (Amazon SES, Postmark, SendGrid, Brevo, Zoho…) with SMTP credentials. Configure SPF, DKIM and DMARC for the `EMAIL_FROM` domain.

## 7. Release checklist

- [ ] `npm ci && npm run lint && npm test && npm run build` pass in CI
- [ ] Environment variables set for both apps; `CLIENT_URL` exactly matches the storefront origin
- [ ] `client/vercel.json` placeholder replaced with the verified Render URL
- [ ] `TRUST_PROXY` verified and set (see "Client IP behind the proxy")
- [ ] Indexes synced on the production database
- [ ] Admin account created (run the seed only on non-production data, or create the admin manually and change the password)
- [ ] Razorpay webhook delivering (check *Webhooks → Logs*)
- [ ] `/health` returns 200; uptime monitor configured
- [ ] Sitemap submitted to Google Search Console
