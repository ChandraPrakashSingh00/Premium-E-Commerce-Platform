# Deployment

Recommended topology: **MongoDB Atlas** (database) · **Render / Railway / AWS** (API) · **Vercel / Netlify** (SPA) · **Cloudinary** (images) · **Razorpay** (payments) · any SMTP provider (email).

## 1. Database – MongoDB Atlas

1. Create a cluster (M10+ for production; M0 works for staging). Atlas clusters are replica sets, so multi-document transactions are enabled automatically.
2. Create a database user with `readWrite` on the app database only.
3. Allow the API's egress IPs (or use private endpoints / VPC peering).
4. Copy the SRV string into `MONGO_URI`, e.g. `mongodb+srv://app:<password>@cluster0.xxxxx.mongodb.net/bluemart?retryWrites=true&w=majority`.
5. Indexes: in production `autoIndex` is disabled. Build them once after the first deploy (and after schema changes):

   ```bash
   cd server
   NODE_ENV=production MONGO_URI="..." node -e "import('./src/config/db.js').then(async ({connectDatabase}) => { await connectDatabase(); const m = await import('./src/models/index.js'); for (const M of Object.values(m)) if (M?.syncIndexes) await M.syncIndexes(); process.exit(0); })"
   ```

## 2. API – Render (blueprint included)

`render.yaml` defines the web service (`rootDir: server`, health check `/health`).

1. New → Blueprint → select the repository.
2. Fill the `sync: false` variables (see table below). JWT secrets are generated by Render.
3. After the first deploy, note the service URL (e.g. `https://bluemart-api.onrender.com`) and set `SERVER_URL` to it.

**Railway**: create a service from the repo with root directory `server`, start command `npm start`, and add the same variables.
**AWS**: build `server/Dockerfile` (ECS Fargate / App Runner). Put it behind an ALB with HTTPS; the app sets `trust proxy` so rate limiting sees real client IPs.

### Server environment

| Variable | Required | Notes |
| --- | --- | --- |
| `NODE_ENV` | ✔ | `production` |
| `PORT` | – | Provided by the platform |
| `MONGO_URI` | ✔ | Atlas connection string |
| `CLIENT_URL` | ✔ | Storefront origin(s), comma-separated. First entry is used in email links |
| `SERVER_URL` | ✔ | Public API origin (sitemap / robots) |
| `JWT_SECRET`, `JWT_REFRESH_SECRET` | ✔ | ≥ 32 chars, different values |
| `COOKIE_DOMAIN` | – | Only when client & API share a parent domain (e.g. `.bluemart.store`) |
| `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET` | for online payments | Without them only COD is offered |
| `RAZORPAY_WEBHOOK_SECRET` | for online payments | Must match the dashboard webhook secret |
| `CLOUDINARY_*` | for uploads | Without them admins can still add image URLs |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `EMAIL_FROM` | for email | Without SMTP, emails are only logged |
| `LOG_LEVEL` | – | `info` by default |
| `REDIS_URL` | – | Reserved for a shared rate-limit store / queue |

> **Cookies across sites.** When the SPA (`*.vercel.app`) and API (`*.onrender.com`) are on different sites, cookies are sent with `SameSite=None; Secure`. Some browsers restrict third-party cookies; the most robust setup is a custom domain for both (`www.bluemart.store` + `api.bluemart.store`) with `COOKIE_DOMAIN=.bluemart.store`, or proxying `/api` through the frontend host (Vercel rewrite `"/api/(.*)" → "https://api.../api/$1"` and `VITE_API_URL=/api/v1`).

## 3. Frontend – Vercel or Netlify

- **Vercel:** import the repo, set *Root Directory* = `client`. `client/vercel.json` configures SPA rewrites and cache/security headers.
- **Netlify:** set *Base directory* = `client`; `client/netlify.toml` configures the build and SPA redirect.

Client environment (build-time, public):

| Variable | Example |
| --- | --- |
| `VITE_API_URL` | `https://api.bluemart.store/api/v1` |
| `VITE_SITE_URL` | `https://www.bluemart.store` (canonical URLs) |
| `VITE_SITE_NAME` | `BlueMart` |

### Sitemap & robots

- The API serves a live `GET /sitemap.xml` and `GET /robots.txt`.
- For the SPA host, generate a static sitemap before building: `MONGO_URI=... CLIENT_URL=https://www.bluemart.store npm run sitemap` (writes `client/public/sitemap.xml`), and update the `Sitemap:` line in `client/public/robots.txt` to your domain. Alternatively add a rewrite from `/sitemap.xml` to the API.

## 4. Razorpay

1. Dashboard → Settings → API Keys → generate (test first, then live).
2. Dashboard → Webhooks → add `https://<api>/api/v1/payments/razorpay/webhook`, set a secret (`RAZORPAY_WEBHOOK_SECRET`), subscribe to `payment.captured`, `payment.failed`, `order.paid`, `refund.processed`, `refund.failed`.
3. Test with Razorpay test cards/UPI (`success@razorpay`) before switching to live keys.

## 5. Cloudinary

Create a product environment, copy cloud name / API key / secret. Uploaded assets go to `<CLOUDINARY_FOLDER>/{products,categories,brands,reviews}` and are converted to WebP (max 2000px).

## 6. Email

Use a transactional provider (Amazon SES, Postmark, SendGrid, Brevo, Zoho…) with SMTP credentials. Configure SPF, DKIM and DMARC for the `EMAIL_FROM` domain.

## 7. Release checklist

- [ ] `npm ci && npm run lint && npm test && npm run build` pass in CI
- [ ] Environment variables set for both apps; `CLIENT_URL` exactly matches the storefront origin
- [ ] Indexes synced on the production database
- [ ] Admin account created (run the seed only on non-production data, or create the admin manually and change the password)
- [ ] Razorpay webhook delivering (check *Webhooks → Logs*)
- [ ] `/health` returns 200; uptime monitor configured
- [ ] Sitemap submitted to Google Search Console
